toon is two files with no dependencies. `toon.css` animates page elements with classes, and `toon.js` animates on `<canvas>`. Use either one, or both.

## Install toon

toon is two files, plus two optional ones. There's no package to install and no build step, and toon isn't published to npm. Each link below downloads its file. The same files are in [`src/` on GitHub](https://github.com/kelseythejackson/toon/tree/main/src).

- <a href="../toon/src/toon.css" download><code>toon.css</code></a> for the CSS presets
- <a href="../toon/src/toon.js" download><code>toon.js</code></a> for the Canvas API (`window.Toon`)

Put them next to your page and include them:

```html
<link rel="stylesheet" href="toon.css">
<script src="toon.js"></script>
```

This works straight from a file on your disk, with no server.

### Optional toon files

- <a href="../toon/src/toon.mjs" download><code>toon.mjs</code></a> lets you use `import` instead of a script tag. It loads `toon.js` from the same folder, so keep the two together. Browsers only load modules over HTTP, so serve the folder with a local server.

  ```js
  import { tween, arc, ease } from './toon.mjs';
  ```

- <a href="../toon/src/toon.debug.js" download><code>toon.debug.js</code></a> is for while you develop. It checks every call's arguments and explains mistakes (see [Errors and debugging](../api/canvas/#errors-and-debugging)).

## toon with frameworks

toon has no framework bindings. You use it the same way as any CSS classes or canvas code.

**React.** Put toon's classes in `className`, as in `<button className="toon-press">`. To replay an effect that plays once (such as `.toon-pop-in`), change the element's `key` so React mounts it again. For canvas work, create the stage in an effect and clean it up on unmount. This is a fragment: replace the comment with drawing code like the one in [Your first Canvas animation](#your-first-canvas-animation).

```jsx
function Thrown() {
  const ref = useRef(null);
  useEffect(() => {
    const stage = Toon.createStage(ref.current);
    stage.loop(() => { stage.clear(); /* draw… */ });
    return () => stage.destroy();      // stops its loops and removes its listeners
  }, []);
  return <canvas ref={ref} style={{ width: '100%', height: 300 }} />;
}
```

**Vue.** Use `:class` and `:key` the same way. Create the stage in `onMounted(() => …)` and call `stage.destroy()` in `onUnmounted`.

**Server rendering (Next, Nuxt, Astro, SvelteKit).** `toon.css` is safe everywhere. `toon.js` uses `window`, so load it only in the browser. Put it in a client-only component, use a dynamic `import('./toon.mjs')` inside the effect, or check `typeof window !== 'undefined'` first.

## Timing and units in toon

- **One clock.** All Canvas motion runs on the ticker (toon's shared clock, `Toon.ticker`). Draw with `stage.loop(fn)` so a canvas stops drawing while it's scrolled out of view.
- **Speed controls run in opposite directions.** In CSS, `--toon-tempo` multiplies duration, so **higher is slower**. In JavaScript, `ticker.timeScale` multiplies time, so **higher is faster**. Setting `ticker.timeScale = 0.25` slows everything down, which helps when you're checking timing.
- **Tweens are awaitable.** `await tween({...})` and `sequence(...)` let you write a whole action as a script. See [Anticipation](../principles/anticipation/).

Each part of toon measures time in one unit:

| Where | Unit |
| --- | --- |
| `tween`, `wait`, `poses`, `stagger` | milliseconds |
| Ticker callbacks and physics | seconds |
| Velocities | pixels per second |

## Composing and debugging toon effects

- **CSS presets compose.** They use the individual transform properties (translate, scale and rotate), so they don't overwrite your `transform`. Two presets that both set `animation` must go on nested elements.
- **Mistakes explain themselves.** Load `toon.debug.js` while you develop: after `toon.js` as a script, or imported before `toon.mjs`. Wrong arguments then throw a message like `toon.arc: end point must be { x, y } numbers`, instead of failing deep inside or drawing nothing.
- **Reduced motion.** `toon.css` turns animation off when the reader's system asks for reduced motion. On canvas that decision is yours; see the [reduced-motion recipe](../recipes/#respect-reduced-motion-on-canvas).

If nothing moves, check these in order:

1. The browser's console or network panel shows no missing `toon.css` or `toon.js`. A missing file means the path is wrong.
2. Your system's reduced motion setting is off. With it on, `toon.css` keeps everything still on purpose.
3. A bouncing element has room above it. Without it, the bounce leaves the top of the page.
4. If you load `toon.mjs`, the page is served over HTTP. Browsers block modules opened from a file.

## toon browser support

Chrome and Edge 116+, Firefox 128+ and Safari 17.2+. toon needs these versions for the individual transform properties and `linear()` easing, and for the `:has()` selector and `color-mix()`. The JavaScript targets ES2020.
