# Product

## Platform

web

## Users

In priority order (confirmed against `site/STYLE.md`):

1. **Front-end developers** adding motion to an interface: buttons that feel pressable, lists that settle in, entrances that don't feel mechanical. They come to get something working in their own project.
2. **Creative coders** working on `<canvas>`, who need a clock, easing, tweens, arcs, squash and stretch, and spring and rope physics without pulling in a framework.
3. **People learning animation**, who pick up the 12 basic principles by seeing each one run, then reading the code behind it.

The reader arrives with a task. They should leave with it done and with a principle understood along the way.

## Product Purpose

toon is a tiny (about 500 lines), zero-dependency library that puts the 12 basic principles of animation into code. It comes in two halves that work together or alone:

- `src/toon.css`: CSS presets added as classes (`.toon-press`, `.toon-follow`, `.toon-bounce`…), tuned with custom properties.
- `src/toon.js`: a Canvas toolkit (`window.Toon`) with one shared clock, easing, tweens, key poses, arcs, squash and stretch, and spring and rope physics. `src/toon.debug.js` is an optional development aid that explains API mistakes.

The docs site (`site/`, Astro Starlight) teaches it: one page per principle with a live demo, CSS, Canvas and tuning tips, plus recipes, a "find an effect" index, and the API reference.

**Success means:**

- **Open-source adoption.** Developers copy toon into real projects, and the docs bring in visitors from GitHub.
- **A portfolio and craft piece.** The library, demos and docs show the author's motion and design craft. The quality of the site is part of the product's argument.

## Positioning

A production library that teaches as you use it. Every preset and function maps to one of the 12 animation principles and is shown live next to its code, so using toon and learning animation happen together. It is small enough to read in one sitting, has no dependencies or build step, and installs by copying two files.

## Operating Context

- **Install:** copy `src/toon.css` and `src/toon.js` into a project. toon isn't published to npm (a local `npm install ../toon` works through the `exports` map).
- **Docs site:** deployed to GitHub Pages at https://kelseythejackson.github.io/toon/ from `main`.
- **Demos:** standalone HTML pages in `examples/` (12 principles, `recipes/`, `start/`) that also open straight from disk. The docs embed them into shadow roots as `<toon-demo>`, each with its own clock.
- **Reader-selectable styles:** four sketchbook styles (Graph Notebook, the default; Riso Press; Cut & Paste; Crayon Cloud), each in light and dark. Readers switch with the pencil menu, and the choice is saved and applied before first paint. Demos follow the active style.
- **Presenting:** the docs and demos work offline once installed, and `?style=…&theme=…` pins the look for a rehearsal or talk.
- **Maintenance:** `npm run check` (size budget, example smoke tests, error handling, demo contrast) and `npm run check:site` (phone widths, links, anchors, script errors) run in CI on every push.

## Capabilities and Constraints

- **Size budget:** the core must stay at or below 520 lines (enforced by `npm run check`).
- **Zero dependencies and no build step** for the library. The JavaScript is ES2020.
- **Browser support:** Chrome and Edge 116+, Firefox 128+, Safari 17.2+.
- **Demo architecture:** every example page wraps its script in `ToonDemos.register(...)`, finds elements through the `document` it is given, and draws only with theme tokens (`DemoTheme`, `examples/demo-tokens.css`), never hex values.
- **Site interface motion** goes through the reusable `fx-` utilities (`site/src/styles/fx.css`, `site/src/scripts/fx.js`). `site/src/scripts/motion.js` is the only file that knows Starlight's selectors (see `site/MOTION.md`).
- **Terms:** use the vocabulary in `site/STYLE.md` (preset vs modifier, demo vs example page, squash and stretch vs Squash & stretch, viewer not audience).
- **Undecided:** whether toon will be published to npm.

## Brand Commitments

- **Name:** "toon", lowercase.
- **Voice:** "A working animator explaining their craft to a developer at the next desk: practical, exact, a little playful, never precious." `site/STYLE.md` is the authority: US English, sentence case, result first, no _we/simply/just/easy_, no exclamation marks in prose, no marketing superlatives.
- **The cast:** Dot (the lead and the logo), Brick, Zip and Loop, generated by `brand/build.py`. Never hand-edit the SVGs. The cast is genderless: use names, never pronouns. Follow the friendliness rules and brand colors in `brand/README.md` (flat fills, no gloss, every face has brows and a mouth, Zip is never drawn without its outline). Characters appear in demos and intros, never inside instructions.

## Product Principles

1. **Result first.** Show the thing moving, then the code, then the why. Teaching rides along with getting work done.
2. **Small enough to own.** Two files to copy, no dependencies, a hard line budget. Every addition has to earn its lines.
3. **The site practices what it teaches.** The docs interface shows the same motion craft it explains, and that is part of the portfolio argument.
4. **Motion is never forced on anyone.** Reduced motion is respected everywhere, and every demo works with it on.
5. **Every snippet runs.** Code shown in the docs comes from real example files where possible, so it can't drift.

## Accessibility & Inclusion

- WCAG AA contrast for every text color pair and every demo color token, in all styles and both modes (`npm run check:contrast`).
- With the OS **Reduce motion** setting on, demos open paused behind a banner with a Play button, and the home page characters stand still.
- Every canvas has `role="img"` and an `aria-label` that describes what moves. Every canvas action also has a real `<button>` or slider.
- Pages must fit 390px and 320px phone widths without pushing the search button off-screen (`npm run check:site`).
- Cast faces keep at least 3:1 contrast against the body, and outlines at least 3:1 against the background.
